## Scope

24 purposefully chosen frames from three previously selected review cases:
`sample_84_1`, `sample_100_3`, `sample_80_2`. Selection uses prior assistant scene
observations to cover different visible content, not certified labels. It is not
random, class-balanced by verified labels, representative of StreamingBench, or
an untouched test. The previous 20-QA counting cohort is not re-scored here.

This separates simple frame categorization from multi-frame counting. Same
SmolVLM2-500M; one image and a generic visual question; max 8 generated tokens.
This changes task, image resolution and input count, so it cannot isolate the
cause of the counting failure or establish a memory-method improvement.

## Frozen categories and paired conditions

Four semantic categories: presenter beside a teaching board; inserted movie or
performance scene; blank/transition; uncertain. Original order A/B/C/D follows
those categories. Cycle order moves old B/C/D/A into new A/B/C/D. Predictions
are mapped to categories before agreement analysis. Images, descriptions and
instructions are identical apart from option order; no labels, QA choices,
timestamps or counts enter inference. First condition alternates 12/12.

Both human and model see the same hash-verified RGB JPEGs (max 640 side, quality 95).
All images are from causal prefixes. Selection IDs/config, source timestamps and
JPEG hashes are in [the portable manifest](manifest.json). Unlike the preceding
fixed raw-result dependency, this selection contract contains no timing fields.
Image files and human labels remain local under ignored `results/`.

## Human review

Open local `results/perception-probe/review.html`. It shows only images and source
timestamps, no model responses and no prefilled categories. Choose a category for
every image; dark presenter lighting alone is not a blank transition. Mark
uncertain rather than guessing. Enter a reviewer alias and explicitly confirm
self-review, then save `human-labels.json` in that same E-drive directory.

Browser progress is stored by manifest hash when local storage is available.
Node tests verify complete-review export and category validation; actual browser
layout/file-picker behavior still needs manual confirmation. A modern browser
may ask for a save location; fallback download requires choosing/moving the file
to the intended E-drive folder. The page uses no external assets or network APIs.

Human provenance is **self-reported**, not independently authenticated. The UI is
blinded to frame-level model responses, but aggregate results and earlier
observations are available to the user; this is not a double-blind study.
No human labels or event counts have been generated by the assistant.

## Commands

From the repository root in the existing virtual environment:

```powershell
python scripts/perception_probe.py prepare `
  --selection configs/perception-probe-v1.json `
  --data-root <path-to-real-time-51-100> `
  --annotations <absolute-path-to-annotations-tail-250.jsonl> `
  --bundle results/perception-probe

python scripts/perception_probe.py run `
  --manifest results/perception-probe/manifest.json `
  --config configs/adaptive-semantic-1fps.yaml `
  --output results/perception-probe/predictions.jsonl --resume

# Only after actual human export:
python scripts/perception_probe.py score `
  --manifest results/perception-probe/manifest.json `
  --predictions results/perception-probe/predictions.jsonl `
  --labels results/perception-probe/human-labels.json `
  --output results/perception-probe/human-scores.json
```

The scorer requires matching manifest hash, complete unique human labels and
validated single-run predictions. Human-uncertain images are excluded from
recognition accuracy; resolved coverage and counts are reported. Invalid/model-
uncertain outputs on resolved labels remain incorrect. Presenter/inserted-scene
balanced recall is available only if both categories have human examples;
per-class recalls and each condition's results remain separate.

The exported source annotation file was derived from earlier baseline records,
as documented for prior probes. Preparing equivalent public data/annotations is
still required. JPEG hash identity can depend on decoding/Pillow versions;
different exports get distinct manifest/run IDs, preventing mixed resumes.
No exact GPU-timing-file replay dependency is introduced in this probe.
